The demo is generated by that repository's `examples/demo.py`. The other boards
were saved by PureRef 2.1.3 during format investigation. These contain synthetic
images and test text, not personal reference boards. Browser tests also modify
decoded rows in memory for crops, nested transforms, and hostile HTML cases;
they never write to these fixtures.

`comments-demo.pur` is the newer generated demo containing group comments. The
test-vault builder installs it as `demo.pur`; it installs the older compact demo
as `automated-demo.pur` so live automation remains fast and deterministic.

`title.pur`, `compact.pur`, `wrapped.pur`, and `rich.pur` are synthetic note
fixtures created with the same reader repository. Their PNGs in `../references/`
were exported by PureRef 2.1.3 (natural size, no canvas background, no image
borders). The optional `../generate-references.py` reproduces these cases in a
fresh temporary directory without changing existing fixtures or user preferences.
Native outer dimensions are 512×62, 531×38, 200×242, and 260×176 respectively.
Browser tests allow 1% difference in automatic widths for native/browser font
metrics, and one pixel in height. These are geometry checks against an independent
renderer, not a claim of pixel-identical text rasterization.

`drawings.pur` and `../references/drawings.png` contain three otherwise identical
width-10 horizontal strokes with option values 0/1/2. The PureRef 2.1.3 export is
800×400 without canvas background or image borders, including children. It verifies
solid, width-scaled 3:2 dashes, and an open end arrow with round caps/joins.

## Adversarial corpus (manual opt-in)

`adv-*.pur` are synthetic files generated by `../generate-adversarial.py` using
the Python writer in the sibling `Vacyyyy/pur-2-file-format` checkout at
`642df197526cfb2e46e4984ae67d11efec7706ba`. Tests consume the committed bytes with
the **installed, pinned TypeScript reader**, not the sibling checkout. No Python,
PureRef, or sibling dependency is needed to run them. The writer's recovered 2.1.3
schema is used; deliberate corruption is isolated to named cases. Unknown format
features are not treated as rendering-fidelity requirements.

`../adversarial-cases.mjs` is the shared inventory and inspection contract.
Geometry/typography/shared-400 exercise supported content; hostile-note exercises
the HTML boundary; graph/resources deliberately mix good and malformed or
unsupported content; item-limit/schema/truncated must fail visibly. The 8,001 ×
8,000 declared resource contains only a 32 × 32 PNG: it tests metadata admission,
not decompression-bomb resistance or peak-memory guarantees.

To intentionally regenerate into a **new** directory:

```sh
python tests/pureref/generate-adversarial.py --reader ../pur-2-file-format --out test-results/new-adversarial
```

Review before copying into this directory. Do not regenerate automatically during tests.
